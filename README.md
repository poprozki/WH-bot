# WH-bot

Бот записи в WhatsApp с веб-панелью. Работает с обычным номером через WAHA,
без WhatsApp Business API. Одна установка обслуживает несколько салонов.

Отвечает клиентам, подбирает свободное время, создаёт и переносит записи,
шлёт напоминания. Язык общения — русский.

## Устройство

| Сервис | Что делает |
|---|---|
| `bot` | Node 22, Express. Диалог, инструменты модели, веб-панель |
| `postgres` | Postgres 17. Все гарантии целостности здесь, а не в коде |
| `waha` | Шлюз WhatsApp, движок NOWEB |
| `asr` | Распознавание голосовых, профиль `voice` |
| `cloudflared` | Публикация панели наружу, профиль `web` |

Двойная запись невозможна на уровне базы: пересечения интервалов режет
`EXCLUDE USING gist`, поэтому гонка двух одновременных заявок заканчивается
отказом одной из них, а не двумя клиентами на одном времени.

Разделение салонов — Row Level Security. Идентификатор арендатора кладётся
в `SET LOCAL` на время транзакции, запрос без него не видит ничего.

Ответ модели проходит проверку перед отправкой: каждая названная цена и
каждое время обязаны встречаться в результатах вызванных инструментов.
Не совпало — ответ не уходит, модель переписывает. Инструкция в промпте
это просьба, ограничение даёт только проверка на выходе.

## Модель

`LLM_PROVIDER` в `.env`:

- `deepseek` — основной, работает кеш промпта
- `openrouter_free` — бесплатно, для сборки и тестов
- `openrouter`, `groq` — запасные

## Запуск

Нужен Docker с плагином compose, для разработки — Node 22.

```bash
cp .env.example .env
./ops/generate-env.sh     # пароли и ключи, вручную не придумывать
```

Дальше вписать в `.env` свой `LLM_API_KEY` и поднять:

```bash
make setup
make up          # без голосовых и панели наружу
make up-voice    # с распознаванием голосовых
make up-all      # плюс панель через Cloudflare
```

Подключение телефона — `make qr`. Номер нужен отдельный, не личный номер
владельца салона: одну сессию нельзя одновременно держать в приложении.

## Панель

По умолчанию на `127.0.0.1:3001`, наружу только через Cloudflare Access.

- `/panel` — расписание и записи
- `/panel/settings` — услуги, мастера, график, характер бота
- `/panel/chats`, `/panel/stats` — диалоги и метрики
- `/panel/console` — песочница: переписка с ботом без WhatsApp
- `/panel/salons` — список салонов, доступ разработчика

`PANEL_DEV_AUTH=1` отключает вход и открывает панель с телефонами всех
клиентов кому угодно. Только для локальной разработки: при
`NODE_ENV=production` процесс с этим флагом не запустится.

## Команды

```bash
make status      # состояние сессии WhatsApp и контейнеров
make logs        # логи бота
make psql        # консоль базы
make backup      # резервная копия
make smoke       # проверка после развёртывания
make down
```

## Разработка

```bash
cd bot
npm install
npm test          # без базы часть тестов пропускается
npm run test:db   # нужен поднятый postgres
npm run migrate   # применить миграции из sql/migrations
```

Миграции идут с `lock_timeout`: если таблица занята, миграция падает,
а не вешает запросы к ней на всё время ожидания блокировки.

Для локальной работы есть `docker-compose.override.yml.example`. Он
открывает порты наружу и отключает вход в панель, поэтому в репозиторий
не входит и на сервере ему делать нечего — compose подхватывает такой файл
сам, без флагов.

```bash
cp docker-compose.override.yml.example docker-compose.override.yml
```

## Про кириллицу в регулярных выражениях

`\b` и `\w` в JavaScript определены через латиницу и с кириллицей не
работают: `/маникюр\b/` не совпадает никогда, причём молча. Вместо границы
слова нужна явная проверка соседнего символа: `(?![а-яё])`. На это уже
пять раз наступали, поэтому в `bot/test/numbers.test.js` стоит тест,
который читает исходник и падает при возврате ошибки.
